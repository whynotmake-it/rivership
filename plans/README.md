## Findings considered and rejected

- **`Curves.ease` "doesn't exist" (docs subagent)**: rejected — it is a real
  Flutter constant; README line 449 is correct.
- **Builders never call `resync` (correctness subagent)**: rejected — the
  builders create their own vsync via `TickerProviderStateMixin`; there is no
  external provider to resync to. `resync` exists for controllers receiving an
  external vsync.
- **`scrubTo` bypasses sync barriers as a bug**: by design — documented on
  `SyncStep` ("seek passes sync freely"). Reduced to a doc cross-reference on
  `scrubTo` (folded into Plan 008).
- **Custom sync token colliding with phase type `P`** in
  `PhaseTrackController.onSyncReleased`: only bites when user tokens share the
  phase enum's type and values; low leverage — not worth doing now.
- **Memoizing `estimateSimulationDuration` results on motion instances**: the
  estimate depends on start/end/velocity, so an instance cache needs a keyed
  map with unbounded growth. The `parent.duration` skip (Plan 006) captures
  most of the win.
- **`_TrimmedSimulation.dx` analytic derivative** (PERF-01): real but deferred
  — the numerical differentiation is 3 extra `x()` evaluations per tick per
  dimension, only for trimmed motions; revisit with profiling evidence.
- **Rewriting `SequenceMotionController` on the new TrackController engine**:
  originally rejected for 2.0 (L effort, MED-HIGH risk). **Overturned
  2026-07-15 by the maintainer as plan 015** — two facts changed the calculus:
  a complete reference implementation exists on the orphaned line
  (`11e92f55`…`b44d6387`), and plan 007's numeric semantics tests now gate the
  rewrite far better than goldens could.
- **README `motor: ^2.0.0` vs pubspec `1.1.0`**: not a standalone plan —
  handled as a release-checklist TODO inside Plan 008.
